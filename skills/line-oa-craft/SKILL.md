# วิจิตรเมนูไลน์ (LINE OA Craft)

rich menu คือ**หน้าแรกของ OA** — คนเปิดแชทมาเจอมันก่อนอย่างอื่น และมันกินพื้นที่ครึ่งจอ
เมนูที่ต้อง**อ่าน**ถึงจะรู้ว่ากดอะไรได้ คือเมนูที่ล้มเหลว เป้าหมายคือ **กวาดตา 1 วินาทีแล้วรู้**

---

## 1 · ข้อจำกัดจริงของ LINE (ผิดข้อเดียว = อัปไม่ผ่านทั้งใบ)

| เรื่อง | ค่าที่ถูกต้อง |
|---|---|
| ขนาดภาพ | **2500×1686** (เต็ม) หรือ **2500×843** (ครึ่ง) — ต้องตรงกับ `size` ใน JSON เป๊ะ |
| **ขนาดไฟล์** | **≤ 1 MB** ★ กับดักที่เจอบ่อยสุด |
| ฟอร์แมต | JPEG หรือ PNG |
| จำนวนช่อง | ≤ 20 · `bounds` ห้ามทับกันและห้ามล้นขอบภาพ |
| `chatBarText` | ≤ 14 ตัวอักษร (แถบล่างที่คนกดเปิดเมนู) |

> ★ **1 MB คือเพดานที่ชนง่ายกว่าที่คิด** — PNG ที่มีมาสคอตหลายตัว + พื้นสีเต็มใบ ทะลุ 1 MB ทันที
> **แก้: ส่งออกเป็น JPEG คุณภาพ 85** (เมนูไม่ต้องการพื้นโปร่งใส) หรือลดจำนวนสีของ PNG
> เช็คก่อนอัปเสมอ: `ls -la` ดูขนาดไฟล์ · เกินแล้วอัปจะเด้งตอนขั้นอัปโหลดภาพ ไม่ใช่ตอนสร้างเมนู

---

## 2 · เจ็ดหลักที่แยกเมนูสวยออกจากเมนูปุ่มเรียง

สกัดจากเมนูไทยที่ทำมาหากินจริง (ป้านวล · MunMuang · อับดุล · Bolt+ · เมนูร้านค้า)

1. **★ ช่องหลักใหญ่ 1 ช่องกินครึ่งบน** — การกระทำที่อยากให้กดที่สุด ที่เหลือเล็กลงชัดเจน
   6 ช่องเท่ากันหมด = ไม่มีลำดับความสำคัญ = ผู้ใช้ต้องคิดเองว่าควรกดอะไรก่อน
2. **★★ ช่องหลักไม่ใช่ปุ่ม มันคือป้ายโฆษณา** — ใส่**ประโยชน์เป็นข้อๆ** ลงในช่องนั้นเลย
   พร้อมป้าย `ใหม่!` ถ้าเพิ่งออก · คนอ่านเมนูแล้วต้องรู้ว่าระบบทำอะไรได้บ้าง ไม่ใช่แค่รู้ว่ากดอะไรได้
3. **ไอคอนต้องต่างกันชัด** — ห้ามใช้มาสคอตตัวเดิมเปลี่ยนท่าเป็นไอคอนทุกช่อง
   คนกวาดตาแล้วเห็น "ตัวการ์ตูนเหมือนกัน 6 ตัว" แล้วต้องอ่านตัวหนังสือทีละช่อง
   **มาสคอตใช้ตัวใหญ่ตัวเดียวในช่องหลัก** ที่เหลือเป็นไอคอนเส้น/แบนคนละรูป
4. **พื้นสีเต็มใบ + การ์ดขาวลอย** — เมนูขาวล้วนกลืนหายในรายชื่อแชทที่คนอื่นสีจัดเต็มจอ
5. **มีสัญญาณว่ากดได้** — เมนูร้านค้าเกือบทุกใบมี `คลิกเลย ▶` เพราะรูปนิ่งไม่มี hover ไม่มีเงา
   **สัญญาณต้องเห็นตั้งแต่ยังไม่แตะ** (มือถือไม่มี hover)
6. **โลโก้ + ป้ายสถานะแพ็ก** ล่างกลาง (`Free` / `Pro`) — บอกตัวตนและเปิดทางขายในภาพเดียว
7. **ช่องขายของแยกสีตัดกับธีม** — ป้านวลใช้ส้มตัดพื้นชมพูสำหรับ "แปลงร่างเป็น Pro"
   **ทำเมื่อมีของขายจริงเท่านั้น** ปุ่มอัปเกรดที่กดแล้วไม่มีอะไรคือการเสียความเชื่อใจฟรีๆ

## 3 · ลำดับลงมือ (ห้ามข้ามข้อ 1)

```
1. เขียนรายการช่อง + จัดลำดับความสำคัญก่อน  ← ตัดสินว่าช่องไหนใหญ่ ตรงนี้ ไม่ใช่ตอนวาด
2. ร่างเลย์เอาต์เป็นตารางพิกัดบนผืน 2500×1686
3. ทำภาพ → ส่งออก → ★ เช็คขนาดไฟล์ ≤ 1 MB
4. แก้ bounds ใน JSON ให้ตรงกับภาพใหม่ทุกช่อง
5. อัปด้วยสคริปต์ → เปิดแชทจริงบนมือถือดูด้วยตา
```

**พิกัดกับภาพต้องแก้พร้อมกันเสมอ** — เปลี่ยนเลย์เอาต์แล้วลืมแก้ `bounds` = กดช่องนี้แต่ไปเปิดอีกจอ
เป็นบั๊กที่ไม่มี error ให้เห็น ต้องกดเองถึงเจอ

**เลย์เอาต์ที่ใช้ได้จริงบนผืน 2500×1686:**
```
┌──────────────────────┬───────────┐   ช่องหลัก  0,0    → 1666×843
│                      │  ช่อง 2    │   ช่อง 2   1666,0  → 834×421
│   ช่องหลัก (ป้าย)     ├───────────┤   ช่อง 3   1666,421→ 834×422
│                      │  ช่อง 3    │   แถวล่าง  y=843   → สูง 843
├──────┬──────┬────────┴───────────┤            แบ่ง 4 ช่อง กว้าง 625
│  4   │  5   │   6    │     7      │
└──────┴──────┴────────┴───────────┘
```

## 4 · กับดักที่เจอจริง

| กับดัก | ผลที่เกิด |
|---|---|
| **ปุ่มชี้ `liff.line.me` ตรงๆ** | บนเดสก์ท็อป/บางเวอร์ชันเปิดไม่ติด — **ต้องชี้โดเมนตัวเองแล้วให้เว็บ redirect** |
| ภาพไม่ตรง `size` ใน JSON | LINE ปฏิเสธ**ทั้งใบ** ไม่ใช่แค่ช่องที่ผิด |
| ไฟล์เกิน 1 MB | เมนูถูกสร้างแล้วแต่ภาพไม่ขึ้น → ผู้ใช้เห็นเมนูเปล่าสีเทา |
| ลืมตั้งเป็นเมนูของ "ทุกคน" | สร้างสำเร็จแต่ไม่มีใครเห็น ต้อง `POST /user/all/richmenu/{id}` |
| รันสคริปต์ติดตั้งซ้ำแล้วไม่ลบใบเก่า | ใบเก่าค้างสะสม (LINE จำกัด 1000 ใบ) — **สคริปต์ต้องเก็บกวาดในรอบเดียว** |
| แก้ภาพแล้วไม่เห็นผลบนมือถือ | LINE แคชภาพเมนู — ปิดแชทเปิดใหม่ หรือรอสักครู่ ไม่ใช่ว่าอัปไม่ติด |

## 5 · ตรวจก่อนบอกว่าเสร็จ

- [ ] ขนาดภาพตรงกับ `size` · ไฟล์ **≤ 1 MB**
- [ ] `bounds` ทุกช่องไม่ทับกัน ไม่ล้มขอบ และ**ตรงกับสิ่งที่ตาเห็นในภาพ**
- [ ] กดครบทุกช่องบนมือถือจริง — ไปถูกจอทุกช่อง
- [ ] ช่องหลักบอก**ประโยชน์** ไม่ใช่แค่ชื่อฟีเจอร์
- [ ] ปิดตาแล้วนึกออกว่าช่องไหนอยู่ตรงไหนจากไอคอน ไม่ต้องอ่านตัวหนังสือ
