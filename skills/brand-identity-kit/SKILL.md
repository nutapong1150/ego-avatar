# อัตลักษณ์แบรนด์ (Brand Identity Kit)

## ทำไมต้องมีสกิลนี้ (บทเรียนจริง 2026-08-22 · KruaCost)

ตั้งชื่อระบบเสร็จ เขียน schema เสร็จ แต่ **ไม่มีใครถามเรื่องสี ธีม โลโก้ mascot landing page เลย** เพราะสกิลที่มีอยู่ไม่มีตัวไหนถือเรื่องนี้:

```
saas-strategy-lens  --> BMC · JTBD · pricing · AARRR
saas-builder-th     --> stack · PDPA/B2B · schema · MVP plan
                          |
                          v   ** ช่องว่าง: ไม่มีใครเคาะอัตลักษณ์ **
landing-page-craft  --> conversion · โครงหน้า · copy   (สมมติว่า "มีแบรนด์แล้ว")
tigr-ui-craft       --> 60-30-10 · glass · motion      (สมมติว่า "มี palette แล้ว")
```

**สกิลนี้อุดตรงกลาง** — เคาะให้จบก่อน แล้วสองสกิลปลายน้ำถึงจะทำงานได้จริง

## เมื่อไหร่ต้องเรียก (ห้ามรอผู้ใช้สั่ง)

- **ทันทีที่ตั้งชื่อระบบ/โปรเจกต์เสร็จ** ← จังหวะหลัก อย่าปล่อยผ่าน
- ก่อนเขียนหน้าจอแรกหรือ `tailwind.config` (ถ้าไม่มี token ก่อน จะได้สีมั่วแล้วต้องรื้อทั้งแอป)
- ก่อนทำ landing page · ก่อนเปิด LINE OA (บอทต้องมีหน้าตาตั้งแต่วันแรก)
- ผู้ใช้เอ่ยคำว่า โลโก้ · ไอคอน · mascot · ธีม · สีแบรนด์ · brand.md

## ผลลัพธ์: `0_public_eco_doc_claude/docs/brand.md` — 7 ช่องนี้ต้องครบ

| # | ช่อง | ถือว่าเสร็จเมื่อ |
|---|---|---|
| 1 | **ตัวตน** | ชื่อ · ชื่อเต็มที่ย่อมา · ชื่อไทย · tagline 1 บรรทัด · ยืนอยู่ตรงไหน (เราไม่ใช่อะไร) |
| 2 | **โทนเสียง** | มีตัวอย่าง ✅/❌ อย่างละ 1 คู่จากข้อความจริงในระบบ ไม่ใช่คำคุณศัพท์ลอย ๆ ("เป็นมิตร ทันสมัย" = ยังไม่เสร็จ) |
| 3 | **สี** | hex ครบชุด + **แบ่ง 60-30-10** + **ความหมายเชิงสถานะ** (แดง=ผิด · ส้ม=ต้องมอง · เขียว=ดี) + สีที่ห้ามใช้พร้อมเหตุผล |
| 4 | **ตัวหนังสือ** | ฟอนต์ + fallback + ขนาดต่ำสุดบนมือถือ + `tabular-nums` ถ้าระบบมีตัวเลขเรียงคอลัมน์ |
| 5 | **โลโก้/ไอคอน** | ทิศทาง + **ต้องอ่านออกที่ 16px** + รายการที่ห้ามใช้ (ของโหลที่ใครก็ใช้) |
| 6 | **Mascot** | ตัวอะไร · นิสัย · ใช้ที่ไหนกี่ท่า · **ห้ามใช้ที่ไหน** — หรือเขียนชัดว่า "ยังไม่ทำ รอจังหวะ X" |
| 7 | **Design tokens** | เขียนจริงลง `design/tokens.css` (ดูโครงโฟลเดอร์ข้างล่าง) แล้ว `brand.md` แค่ชี้ไปหา ไม่ต้องก๊อป hex มาซ้ำ |

ปิดท้ายด้วยหัวข้อ **"ยังค้าง (ต้องผู้ใช้เคาะ)"** — ทุกอย่างที่ยังเดาอยู่ต้องโผล่ตรงนี้ ห้ามซ่อน

## โครงโฟลเดอร์มาตรฐาน (บังคับ — ทุกโปรเจกต์ต้องเหมือนกัน)

```
<workspace>/
├── design/
│   └── tokens.css          <- **แหล่งความจริงเดียวของสี** ห้ามพิมพ์ hex ที่อื่น
├── assets/
│   ├── logo/               favicon-32 · favicon-180 · logo-icon · logo-horizontal · logo-vertical
│   ├── mascot/             README.md (กฎตั้งชื่อ+ท่าที่ต้องมี) + ไฟล์ท่า
│   └── line-oa/            README.md (ตารางขนาด) + รูปโปรไฟล์/ปก/ทักทาย/rich menu + rich-menu.json
└── 0_public_eco_doc_claude/docs/brand.md   <- **เหตุผล** ว่าทำไมถึงเลือกสี/ฟอนต์/mascot แบบนั้น
```

**แบ่งหน้าที่ให้ชัด อย่าเขียนซ้ำกัน:**
- `brand.md` = **เหตุผลและกฎ** (คนอ่าน) — ทำไมสีนี้ · ห้ามใช้อะไร · โทนเสียง · บรีฟ mascot
- `design/tokens.css` = **ค่าที่เครื่องอ่าน** (โค้ดใช้จริง) — เปลี่ยนธีมทั้งระบบด้วยการเขียนทับไฟล์เดียว

**ชื่อ token ต้องเหมือนกันทุกโปรเจกต์** (ย้ายคนข้ามโปรเจกต์แล้วไม่ต้องเรียนใหม่ · ก๊อปคอมโพเนนต์ข้ามงานได้เลย):
```
--color-primary / -hover · --color-secondary · --color-accent
--color-bg · --color-surface · --color-surface-hover · --color-border · --color-border-strong
--color-text · --color-text-muted · --color-text-inverse
--color-success/-bg · --color-warning/-bg · --color-danger/-bg
--color-line / -hover        (ใช้เฉพาะจุดที่พูดถึง LINE จริงๆ)
--font-display · --font-sans · --font-mono
--radius-sm/-md/-lg/-full · --shadow-card
```

**`tokens.css` ต้องมี dark mode ครบ 3 สถานะเสมอ** — `:root` (สว่างเต็มชุด) · `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])` · `:root[data-theme="dark"]` · **ชื่อ token ห้ามเปลี่ยน** โค้ดที่เรียก `var(--…)` จะได้ไม่ต้องแก้สักบรรทัด

**กฎ dark mode ที่พลาดบ่อย:** สีแบรนด์ต้อง**สว่างขึ้น**ในโหมดมืด ไม่ใช่ใช้สีเดิม (จมพื้น) · `--color-text-inverse` ในโหมดมืดต้องกลายเป็น**สีเข้ม** เพราะตัวอักษรไปอยู่บนปุ่มสีสว่าง · พื้นมืดใช้ดำอมสีแบรนด์ ไม่ใช่ดำสนิท

**ตอนเสนอธีมให้ผู้ใช้เลือก: ต้องโชว์ทั้งโหมดสว่างและมืดคู่กันเสมอ** และวางบน**ของจริงที่ผู้ใช้ต้องมองทุกวัน** (ตาราง ตัวเลข ปุ่ม ป้ายสถานะ) ไม่ใช่แถบสีลอยๆ — palette ที่สวยในกล่องสี่เหลี่ยมกับ palette ที่อ่านตัวเลขไหวคนละเรื่องกัน

## วิธีทำงาน

1. **ถามรวดเดียว 3-4 ข้อ** (`AskUserQuestion`) — ทิศทางสี · mascot เอาไหมและใช้ตอนไหน · landing page ทำตอนไหน · อย่างอื่นเดาให้แล้วให้แก้
2. **เดาให้ก่อนเสมอ อย่าถามช่องเปล่า** — เสนอ palette พร้อม hex ให้ค้านง่ายกว่าถามว่า "อยากได้สีอะไร"
3. **ขุดจากโลกของงานจริง** — ระบบครัวหยิบสีจากครัว (เขียวครัว ครีม ส้มอิฐ) ไม่ใช่ palette SaaS สำเร็จรูป · ถ้าเคยทำ asset อะไรไปแล้ว (เช่น หัวตารางใน Excel template) **ให้ยึดสีนั้นเป็นหลัก** จะได้ไม่มีสองแบรนด์
4. **เขียน `brand.md`** แล้วค่อยส่งต่อ `landing-page-craft` (โครง+copy) · `tigr-ui-craft` / `ux-four-masters` (ความสวย)
5. **จังหวะที่ต้องกล้าบอกว่ายังไม่ต้องทำ** — โลโก้เต็มรูปแบบ · mascot · landing page ที่มี copy อวดผลลัพธ์ **รอ MVP ใช้ได้ก่อน** · แต่ **สี/ธีม tokens · tagline · โทนเสียง ต้องมีตั้งแต่ก่อนโค้ดบรรทัดแรกของ UI**

## กฎเหล็ก

- **ห้ามเขียน hex ตรง ๆ ในคอมโพเนนต์** ทุกสีต้องมาจาก `var(--…)` ที่ประกาศใน `design/tokens.css` ที่เดียว
- **สีเชิงสถานะแยกจากสีแบรนด์** — ดี/เตือน/ผิด ห้ามใช้สีเดียวกับปุ่มหลัก ไม่งั้นอ่านตัวเลขผิดความหมาย
- **mascot ห้ามโผล่ในหน้าตัวเลข/รายงาน** — ที่นั่นต้องจริงจัง
- **ทุกสมมติฐานที่ยังไม่ได้เคาะ ต้องอยู่ในหัวข้อ "ยังค้าง"** ห้ามเขียนเหมือนตัดสินใจแล้ว (เช่น ราคา · โดเมน · ปลายทางปุ่ม CTA)

## บทเรียนจากสนามจริง (KruaCost · 2026-08-22)

### กับดัก Tailwind v4 × tokens.css — ชื่อชนกันแล้วตัวแปรอ้างวนใส่ตัวเอง
`@theme inline` ของ Tailwind ใช้ namespace `--color-*` `--font-*` `--radius-*` **ชุดเดียวกับที่ tokens.css มักตั้ง**
เขียน `--color-primary: var(--color-primary)` = ตัวแปรอ้างตัวเอง พังเงียบ ไม่มี error
**ต้องแมปเป็นชื่อคนละชุด** แล้วจดแผนที่ชื่อไว้ในไฟล์:
```css
@theme inline {
  --color-ink: var(--color-primary);    /* bg-ink text-ink */
  --color-paper: var(--color-bg);
  --radius-token-md: var(--radius-md);  /* ห้ามใช้ --radius-md ตรงๆ */
}
```
ตั้งชื่อฝั่ง Tailwind ด้วย**ภาษาแบรนด์** (ink/paper/stamp/rule) จะได้อ่านออกว่าหมายถึงอะไร

### สีสถานะต้องแยก "ทิศทางของเงิน" ออกจาก "คำเตือนของระบบ"
ธีมที่มีแดง 2 เฉด (แดงแบรนด์ + แดง error) คนแยกไม่ออกแน่นอน — อย่าแก้ด้วยการเขียนกฎกำกับ **ให้ทำให้มันไม่เหมือนกันตั้งแต่แรก**
```
rise    แดง     ราคาขึ้น · ต้นทุนขึ้น · เกินเป้า   = เงินแย่ลง ไม่มีใครผิด ไม่มีอะไรให้กด
warning อำพัน   แมปไม่ได้ · ยอดไม่ตรง · ยังไม่มีราคา = ระบบรอให้คนลงมือจัดการ
success เขียว   ลดลง · เข้าเป้า · สำเร็จ
danger  แดงเข้ม ค่าผิด · บันทึกไม่สำเร็จ · ลบ
```
**กฎการทาสี:** ทาบน *การเปลี่ยนแปลง* กับ *การตัดสิน* เท่านั้น **ห้ามทาบนข้อเท็จจริง**
(`88.00 บาท` ไม่ทา · `↑ 151% จาก 35` ทา · `food cost 39.8% เกินเป้า` ทา · `ต้นทุน/จาน 127.27` ไม่ทา)

### ต้องวัด contrast ของสีตัวหนังสือรอง ไม่ใช่แค่เลือกให้ดูสวย
`--color-text-muted` ที่เลือกมาสวยๆ มักตก 4.5:1 — ของ KruaCost ได้ 4.20:1 ทั้งที่ใช้กับ "วันที่ · หน่วย · ราคาเดิม" ที่ต้องอ่านออกจริง
**เขียน token เสร็จให้วัดทุกคู่ที่เป็นตัวหนังสือบนพื้น** แล้วจดค่าที่วัดได้ไว้ใน comment พร้อมเหตุผลที่เปลี่ยน
