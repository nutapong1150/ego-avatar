# ทะเบียนสเปก (Spec Ledger)

## ปัญหาที่สกิลนี้แก้

แผนที่เขียนเป็นเรียงความจะ **เน่าเงียบๆ** — อ่านผ่านแล้วรู้สึกว่าครบ แต่:

- ไม่รู้ว่าข้อไหน "ตัดสินแล้ว" ข้อไหน "แค่คิดดังๆ"
- ไม่รู้ว่าอันไหน **ตรวจจากแหล่งจริง** อันไหน **เดาเอา** → เดาผิดข้อเดียวล้มสถาปัตยกรรมทั้งอัน
- session ถัดไปมาเสนอของที่เคยตีตกไปแล้ว เพราะไม่มีใครจดว่า "ทางนี้ไม่เอา เพราะ..."
- แก้ข้อ 30 แล้วข้อ 12 ตายโดยไม่มีใครรู้

**ทางแก้: จดเป็นทะเบียนที่มีเลข ไม่ใช่เรียงความ** — ของทุกชิ้นมีที่อยู่ อ้างถึงกันได้ ตายได้อย่างเปิดเผย

---

## 4 ทะเบียน

```
หลักการห้ามละเมิด (ข้อ 1-N)   ← กฎที่ทุกการตัดสินใจใหม่ต้องผ่าน · เปลี่ยนยากที่สุด
        ▲
        │ ตกผลึกขึ้นมาจาก
        │
   D1..Dn  การตัดสินใจ  ◄──── ปิดช่องโหว่ ──── G1..Gn  ช่องโหว่
        │                                          ▲
        │ ถูกล้มโดย                                 │ โผล่จาก
        ▼                                          │
   F1..Fn  ข้อเท็จจริงที่ตรวจจากแหล่งจริง      user flow ที่เขียนจนจบ
```

### D — ทะเบียนการตัดสินใจ

หนึ่งข้อ = หนึ่งการตัดสินใจ **ที่ปิดแล้ว** เขียนติดกันไปเรื่อยๆ ห้ามเรียงใหม่ ห้ามใช้เลขซ้ำ

```markdown
## D28 🔒 — <สรุปสั้นเป็นประโยคบอกเล่า> (YYYY-MM-DD)

<สิ่งที่ตัดสิน — เขียนให้คนที่ไม่อยู่ในวงสนทนาทำตามได้>

**เหตุผล:** <ทำไมถึงเลือกทางนี้>
**ทางที่ไม่เลือกและเพราะอะไร:** <สำคัญที่สุด — นี่คือสิ่งที่กัน session หน้ามาเสนอซ้ำ>
**ราคาที่ยอมจ่ายแล้ว:** <ข้อเสียที่รู้ตัวและรับได้>
```

กฎ:
- **🔒 = ปิดแล้ว ห้ามรื้อโดยไม่มีข้อมูลใหม่** · ไม่มี 🔒 = ยังขยับได้
- **กลับคำต้องเขียนตรงๆ** ว่า *"กลับคำ D22 ในส่วน X — ส่วนอื่นของ D22 ยังยืน"* **ห้ามลบของเก่าทิ้ง**
  ประวัติการกลับคำคือสิ่งที่บอกว่าเราเรียนรู้อะไรมา
- ของที่ **"พิจารณาแล้วไม่เอา"** ให้จดไว้ใต้ D ที่เกี่ยวข้อง พร้อมตัวเลข/เหตุผล — ไม่งั้นจะถูกเสนอใหม่ทุก 2 เดือน

### F — ทะเบียนข้อเท็จจริงที่ตรวจจากแหล่งจริง

**ทะเบียนที่หายากที่สุดและมีค่าที่สุด** — แยก "ที่รู้" ออกจาก "ที่เดา" อย่างเด็ดขาด

```markdown
## F10 📖 — <ข้อเท็จจริง> (ตรวจ YYYY-MM-DD)

**คำถาม:** <เราสงสัยอะไร>
**คำตอบ:** <ที่เจอจริง พร้อมตัวเลข>
**แหล่ง:** <URL หรือหน้าเอกสารทางการ — ยืนยันกี่แหล่ง>
**ล้มอะไรไปบ้าง:** <D ข้อไหนตายเพราะข้อเท็จจริงนี้>
```

กฎเหล็ก:
- **ห้ามเอาความจำมาเขียนเป็น F** — F ต้องมาจากการเปิดเอกสารทางการจริงๆ ในวันนั้น
- ข้อจำกัดของแพลตฟอร์ม (โควต้า · timeout · ขนาดไฟล์ · สิทธิ์ที่ต้อง verify) **เปลี่ยนทุกปี**
  ตัวเลขที่ถูกเมื่อปีที่แล้วคือระเบิดเวลา
- **สมมติฐานที่ไม่เคยตรวจคือหนี้ที่แพงที่สุดในแผน** — มันไม่ส่งเสียงจนวันที่เราลงมือ

### G — ทะเบียนช่องโหว่

ของที่ **flow ชี้ให้เห็นว่าไม่มีใครตัดสิน** — ไม่ใช่บั๊ก ไม่ใช่ฟีเจอร์ แต่คือ "รูในแผน"

```markdown
| # | ช่องโหว่ | โผล่จาก flow ไหน | สถานะ |
|---|---|---|---|
| G6 | ชื่อกลุ่มดึงไม่ได้ถ้าไม่ verified แต่มันคือชื่อโฟลเดอร์ถาวร | F1 | ✅ ปิดด้วย D41 |
| G10 | token ประจำกลุ่มไม่มีวันหมดอายุ | F3 | 🟠 เสี่ยงต่ำ ยังเปิด |
```

ปิดแล้วต้องเขียนว่าปิดด้วย D ข้อไหน · ยังเปิดต้องเขียนว่าติดอะไร · **ห้ามลบแถวที่ปิดแล้วทิ้ง**

### หลักการห้ามละเมิด

กฎ 5-8 ข้อที่ **ทุกการตัดสินใจใหม่ต้องผ่าน** ตกผลึกมาจาก D หลายข้อที่พูดเรื่องเดียวกัน

```markdown
| # | หลักการ | ที่มา |
|---|---|---|
| 4 | ไฟล์ตัวเต็มไม่วิ่งผ่านเซิร์ฟเวอร์เรา | D15 |
| 7 | ปัญหาที่แก้ที่ LINE ไม่ได้ ให้ลง LIFF ก่อนเสมอ | D42 |
```

ประโยชน์จริง: เจอข้อเสนอใหม่ปุ๊บ **เอามาทาบกับ 7 ข้อนี้ก่อน** ถ้าชนข้อไหนคือรู้ทันทีว่าต้องคุยเรื่องอะไร

## ลูปการทำงาน

```
1. เขียน user flow ให้จบทุกเส้น  ──► 2. ใช้ flow ล่าช่องโหว่ (G)
        ▲                                        │
        │                                        ▼
6. ตกผลึกเป็นหลักการ  ◄── 5. ปิดเป็น D ◄── 4. ตรวจข้อเท็จจริงที่ต้องใช้ (F)
   (เมื่อ D ซ้ำธีมกัน)                            ▲
                                                 │
                              3. grill เจ้าของเรื่องทีละรอบจนไม่เหลือที่สมมติ
```

**ขั้นที่ 1 คือขั้นที่คนข้ามบ่อยที่สุดและแพงที่สุด** — user flow ไม่ใช่เอกสารประกอบ
มันคือ **เครื่องมือขุด** · เขียน flow ให้จบเส้นเดียวมักเจอรูที่นั่งคิดเฉยๆ ทั้งเดือนก็ไม่เจอ

**ขั้นที่ 3 ใช้สกิล `grilling`** — ถามทีละรอบ ทุกคำถามมีข้อเสนอของเราแนบไปด้วย
รอบต่อไปถามเฉพาะข้อที่ปลดล็อกแล้วจริงๆ

## กฎเหล็ก 8 ข้อ (สกัดจากสนามจริง)

### 1. หาข้อเท็จจริงเป็นหน้าที่เรา ตัดสินใจเป็นหน้าที่เจ้าของ
ห้ามถามเจ้าของเรื่องในสิ่งที่เปิดเอกสารดูเองได้ · และห้ามตัดสินใจแทนในสิ่งที่เป็นรสนิยมหรือธุรกิจของเขา

### 2. เจอตัวเลขที่ล้มสมมติฐานตัวเอง ต้องพูดทันทีและพูดตรงๆ
ตัวอย่างจริง: เคยรายงานว่า push เข้ากลุ่ม LINE = 1 ข้อความ → ตรวจแล้วพบว่า**นับตามจำนวนคนในกลุ่ม**
เพดานจาก "69 กลุ่ม" เหลือ "6 กลุ่ม" ซึ่งพลิกการตัดสินใจทั้งข้อ · **แก้แล้วเดินต่อ ไม่ต้องขอโทษยาว**

### 3. ของที่ "สร้างแล้วแก้ไม่ได้" ต้องมีขั้นให้มนุษย์ยืนยัน
ชื่อโฟลเดอร์ · ชื่อไฟล์ · id ที่ฝังในลิงก์ที่คนเอาไป bookmark · โครงโฟลเดอร์ที่ไฟล์เก่าอยู่ในนั้นแล้ว
สิ่งพวกนี้ **แก้ทีหลัง = migration บนข้อมูลจริงของลูกค้า** · จ่ายบรรทัดเดียวบนจอวันนี้ ถูกกว่ามาก

### 4. หน่วยที่ตรงกับ "จังหวะเจ็บ" ของผู้ใช้ ชนะหน่วยที่สวยทางเทคนิค
เดือน (เบิกงวด/ปิดงบ/ยื่นภาษี) ชนะสัปดาห์ แม้สัปดาห์จะซอยละเอียดกว่า
**ถามเสมอ: ผู้ใช้เจ็บเป็นรอบอะไร** แล้วใช้รอบนั้นเป็นหน่วย

### 5. ยอมรับความไม่รู้บนจอที่แก้ได้ ไม่ใช่ในของที่แก้ไม่ได้
ดึงชื่อคนไม่ได้ → เขียน "ไม่ทราบผู้ส่ง" **บนจอ** ได้ · แต่ห้ามแช่คำนั้นลงใน**ชื่อไฟล์ถาวร**
ความล้มเหลวชั่วคราว 2 วินาที ไม่ควรถูกจารึกไว้ตลอดชีวิตของข้อมูล

### 6. สัญญาณต้องหายได้ บันทึกต้องอยู่ครบ — อย่าใช้กรอบเวลาเดียวกัน
แถบเตือน = สัญญาณ (นับสั้น เพื่อให้ยังมีความหมายตอนโผล่)
หน้ารายการ = บันทึก (เก็บครบ เพื่อให้ตามย้อนได้)
ใช้กรอบเดียวกันเมื่อไหร่ จะได้ไฟแดงค้างที่คนเลิกมอง

### 7. อย่าเพิ่งเชื่อว่า "ต้องเพิ่มคอลัมน์" — แต่ถ้าต้องเพิ่มจริงให้เพิ่มตอนนี้
ช่องโหว่ส่วนใหญ่ปิดได้ด้วยกลไกที่มีอยู่แล้ว **ถามก่อนเสมอว่ามีของเดิมทำได้มั้ย**
แต่พอเจอข้อที่ต้องเพิ่มจริง (เช่นตาราง log ที่ไม่มีข้อมูลระบุตัวสิ่งที่ log)
**เพิ่มตอนที่ยังไม่มีโค้ด = ฟรี · เพิ่มหลัง prod = migration**

### 8. ทุกข้อความที่ระบบพูดกับผู้ใช้ อยู่ในไฟล์เดียว
ห้ามเขียนข้อความใหม่ในโค้ด · ต้องการข้อความใหม่ = ไปเพิ่มในไฟล์นั้นก่อน
ผลพลอยได้ที่ใหญ่กว่าที่คิด: เวลาออกแบบฟีเจอร์ใหม่จะเห็นทันทีว่า **"ฟีเจอร์นี้ไม่ต้องเพิ่มข้อความเลย"**
ซึ่งมักแปลว่าออกแบบมาถูกทาง

## ห้ามทำ

- ❌ ลบ D หรือ G เก่าทิ้งเมื่อกลับคำ → ให้เขียนทับด้วยข้อใหม่ที่อ้างถึงข้อเก่า
- ❌ เขียน F จากความจำ → F ต้องมีแหล่งและวันที่ตรวจ
- ❌ เขียนแผนเป็นเรียงความไม่มีเลข → อ้างถึงไม่ได้ = คิดซ้ำแน่นอน
- ❌ ตัดสินใจแทนเจ้าของในเรื่องรสนิยม/ธุรกิจ → เสนอพร้อมเหตุผล แล้วรอ
- ❌ ปล่อยให้ "ยังเปิดอยู่" หายไปจากท้ายเอกสาร → ของที่ยังไม่ตัดสินต้องมองเห็นตลอดเวลา
