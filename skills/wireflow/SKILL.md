# Wireflow: User Flow → หน้าจอ → ตรวจ traceability

**Wireflow** (คำของ Nielsen Norman Group) = user flow ที่ใช้หน้าจอจริงเป็นโหนด แก่นของสกิลนี้คือ **traceability**: ลูกศรทุกเส้นใน flow ต้องเป็นปุ่มจริงบนหน้าจอ และปุ่มทุกปุ่มบนหน้าจอต้องเป็นลูกศรใน flow ขาดข้างไหนคือแบบยังไม่เสร็จ

```
① ตั้งฐาน ──► ② User Flow ──► ③ หน้าจอ (รวมหน้าสถานะ) ──► ④ ตรวจ 3 ทาง ──► ⑤ แก้แล้วส่ง
   ธีม+ข้อมูล      ทุกโหนด =       ทุกปุ่ม = ลูกศร              สคริปต์ +          check.md
   ตัวอย่างชุดเดียว   <a href> ไปหน้าจอ                            ตัวเลขข้ามหน้า
```

## ผลลัพธ์
เก็บที่ `0_public_eco_doc_claude/design/<ชื่อระบบ>/` (ตามกฎศูนย์เอกสาร) เว้นแต่ท่านกำหนดที่อื่น
- `flow.html` — แผนภาพ flow **ทุกโหนดเป็น `<a href="screens/X.html">`** (flow กดเข้าหน้าจอได้ และสคริปต์ตรวจได้ว่าทุกหน้าอยู่ใน flow)
- `screens/*.html` — หนึ่งไฟล์ต่อหนึ่งหน้า HTML + inline style ล้วน ลิงก์หากันด้วย `<a href>` จนคลิกไล่ได้ทั้ง flow
- `check.md` — ผลตรวจ

ต้องการดูบนมือถือ → publish `flow.html` เป็น Artifact พร้อม `files` ของ `screens/` (ลิงก์สัมพัทธ์ใช้ได้)

## ขั้นตอน

### ① ตั้งฐาน
- เป้าหมายโปรดักต์ · ผู้ใช้หลัก · อุปกรณ์หลัก (มือถือ 390×844 / คอม 1440×900)
- ธีม: มี `brand.md` จาก `brand-identity-kit` ให้ใช้ตามนั้น ไม่มีให้ตั้งเอง — สีพื้น/การ์ด/เส้นขอบ/ตัวอักษร/รอง · สีหลัก 1 สี · เตือน/ผิดพลาด · ฟอนต์ Google Fonts 2–3 ตัว
- **ข้อมูลตัวอย่างชุดเดียว** ใช้ทุกหน้า (ชื่อไฟล์ ตัวเลข ราคา ยอดคงเหลือ) เขียนเป็นตารางไว้บนสุดของ `check.md` ก่อนวาดหน้าแรก
- เว็บคู่แข่งเป็นแรงบันดาลใจได้แค่แนวทาง ห้ามลอกชื่อ โลโก้ ข้อความ เลย์เอาต์

**เสร็จเมื่อ:** มีตารางธีม + ตารางข้อมูลตัวอย่างใน `check.md`

### ② User Flow (`flow.html`)
- flow ครบ 3 ชุดตาม `diagram-first`: **ตั้งต้น** (เข้าครั้งแรก) · **รอบประจำ** (งานหลักที่ทำซ้ำ) · **ทางแตก/ล้มเหลว** (สิทธิ์ไม่พอ, ผิดพลาด, ถูกขัดจังหวะ, ยกเลิก)
- โหนด = หน้าจอ มีรหัส: `S1, S2…` หน้ารอง `S2b` หน้าคอม `D1`
- โหนดเงื่อนไข = กรอบเส้นประสีเตือน · โหนดผิดพลาด = เส้นประสีผิดพลาด
- ลูกศรมีป้าย และแยกสีตามชนิด: หลัก / จ่ายเงิน / ทางแยก / ฟีเจอร์อนาคต (เส้นประ)
- ฟีเจอร์ที่ทำทีหลัง แยกกรอบ ติดป้าย "เฟสสุดท้าย"
- การ์ด "หลักการของ flow" 3–5 ข้อ (กติกาที่ทุกหน้าต้องเคารพ เช่น "จ่ายแล้วกลับหน้าที่มา")
- ตารางทางแยก: จาก | เงื่อนไข | ไป

**เสร็จเมื่อ:** ทุกโหนดเป็นลิงก์ไปไฟล์หน้าจอ (ไฟล์ยังว่างได้) และมีทั้ง 3 ชุด

### ③ หน้าจอ (`screens/*.html`)
- ปุ่มจริงเท่านั้น: `<a href>` / `<button>` / `<input>` คู่ `<label>` · ปุ่มสูง ≥ 44px · คอนทราสต์ ≥ 4.5:1
- ข้อความจริงทั้งหมด ไม่มี lorem ipsum ตัวเลขมาจากตารางข้อมูลตัวอย่างเท่านั้น ข้อมูลที่ไม่รู้ใช้ `[ชื่อผู้ใช้]`
- **หน้าสถานะเป็นหน้าจอเต็มตัว** ไม่ใช่หมายเหตุ: สิทธิ์/เครดิตไม่พอ · ผิดพลาด (บอกหลุดขั้นไหน + เสียเงินไหม + ทางออก) · กำลังโหลด/ประมวลผล · ถูกขัดจังหวะ · สำเร็จ
- ปุ่มที่ยังไม่มีปลายทาง → `href="#ชื่อ"` (สคริปต์จะรวบเป็น "ลิงก์จำลอง")

**เสร็จเมื่อ:** ทุกโหนดใน flow มีไฟล์หน้าจอที่ออกแบบแล้ว และทุกทางแตกใน flow มีหน้าสถานะของตัวเอง

### ④ ตรวจ 3 ทาง (วัดจริง ห้ามกวาดตา)
1. **หน้าจอ → Flow (สคริปต์):**
   ```bash
   node "<โฟลเดอร์สกิลนี้>/check-links.mjs" screens flow.html
   ```
   จับให้: ลิงก์เสีย · แท็กเปิด/ปิดไม่ครบ · หน้าที่ไม่อยู่ใน flow (exit 1) · หน้าที่ไม่มีปุ่มพาเข้า · ลิงก์จำลองทั้งหมด
   หน้าที่ไม่มีปุ่มพาเข้า **ต้องเป็นหน้าที่ระบบเปิดเอง** (สถานะ/ผิดพลาด/หน้าคอม) — ถ้าไม่ใช่ คือหน้าหลุด
2. **Flow → หน้าจอ (ตาราง):** ลูกศรทุกเส้น | ปุ่มไหนบนหน้าไหน | ผ่าน/ขาดหน้าย่อย/ไม่มีหน้าจอ — สคริปต์บอกได้แค่ว่าลิงก์มี แต่ไม่รู้ว่าป้ายลูกศรกับป้ายปุ่มตรงความหมายกัน
3. **ตัวเลขข้ามหน้า:** ทุกตัวเลขที่ซ้ำหลายหน้า (เวลา เครดิต ราคา ยอดคงเหลือ) ตรงกับตารางข้อมูลตัวอย่าง และบวกลบแล้วถูก

**เสร็จเมื่อ:** สคริปต์ผ่าน (exit 0) · ตารางลูกศรครบทุกเส้น · ตัวเลขทุกตัวถูกอ้างถึงตาราง

### ⑤ แก้แล้วส่ง
- **แก้ก่อนส่ง** ทุกอย่างที่แก้ได้ แล้วรันสคริปต์ซ้ำ
- `check.md` สรุป: ผลแต่ละทาง · รายการที่แก้ระหว่างตรวจ · ลิงก์จำลอง · หน้าที่ระบบเปิดเอง · **สิ่งที่ยังไม่ได้ออกแบบ** (เขียนตรง ๆ ห้ามปล่อยให้คนอ่านคิดว่าครบ)

## กับดักที่เจอจริง (TSub 2026-09)
- flow เขียนว่า "เปิดได้จากทุกหน้า" แต่ปุ่มมีจริงแค่ 2 หน้า → เขียน flow ให้ตรงปุ่ม ไม่ใช่ตรงความตั้งใจ
- ลิงก์ "ดูราคา" จากหน้าแรกพาไปจ่ายเงินได้โดยไม่ล็อกอิน → ทางเข้าจ่ายเงินทุกทางต้องผ่านเงื่อนไขเดียวกัน
- จ่ายแล้วกลับหน้าเดิมเสมอ ทั้งที่มาได้จาก 2 หน้า → ใช้ "กลับหน้าที่มา" และระบุทุกหน้าที่มาได้
- หน้าหลักโชว์งาน "ค้างไว้" ทั้งที่ยอดคงเหลือพอ → ตัวเลขกับสถานะต้องมาจากตารางข้อมูลตัวอย่างเดียวกัน
- หน้าคอมเขียนว่า "ซิงก์ทุกอย่าง" ขัดกับหลักการ flow ("วิดีโอไม่ออกจากเครื่อง") → ข้อความบนหน้าจอทุกข้อต้องผ่านการ์ดหลักการ
- ปุ่ม "รอรอบใหม่" ไม่ไปไหน → ปุ่มทางเลือกบนหน้าสถานะต้องมีปลายทางทุกปุ่ม

## ใช้คู่กับ
- ก่อน: `brand-identity-kit` (ธีม) · `spec-ledger` (บันทึกการตัดสินใจที่ flow เผยออกมา) · `diagram-first` (บังคับให้มี flow)
- ขัดเกลาภาพ: `tigr-ui-craft` / `hallmark` / `impeccable-ui` — เรียกหลัง ③ ผ่านแล้ว ห้ามให้การขัดภาพทำลาย traceability
- หลังสร้างระบบจริง: `system-test-sweep` เดินระบบจริงเทียบกับ wireflow นี้
