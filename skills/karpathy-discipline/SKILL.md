# วิถีคาร์พาธี (Karpathy's Discipline)

**ประเภท:** Unique Skill
**ที่มา:** กลืนกินจาก [andrej-karpathy-skills/karpathy-guidelines](https://github.com/multica-ai/andrej-karpathy-skills) (MIT) ซึ่งกลั่นจากข้อสังเกตของ Andrej Karpathy เรื่องกับดักของ LLM เวลาเขียนโค้ด — **สกิลนี้มีเนื้อหาครบในตัวเอง ไม่ต้องพึ่งปลั๊กอินภายนอกแล้ว**

**Tradeoff ที่ยอมรับ:** กฎชุดนี้เอียงไปทาง "ระวังไว้ก่อน" มากกว่า "เร็วไว้ก่อน" งานจิ๊บๆ ใช้วิจารณญาณได้

---

## 1. คิดก่อนพิมพ์ (Think Before Coding)

**ห้ามเดา ห้ามซ่อนความไม่แน่ใจ ต้องวางทางเลือกให้เห็น**

ก่อนลงมือ:
- บอกสมมติฐานออกมาตรงๆ ถ้าไม่แน่ใจ → ถาม
- ถ้าโจทย์ตีความได้หลายทาง → วางให้เห็นทุกทาง ห้ามเลือกเงียบๆ เอง
- ถ้ามีทางที่ง่ายกว่า → พูด และเถียงได้ถ้ามีเหตุผล
- ถ้ามีอะไรไม่ชัด → **หยุด** ระบุว่าสับสนตรงไหน แล้วถาม

## 2. เรียบง่ายไว้ก่อน (Simplicity First)

**โค้ดน้อยที่สุดที่แก้ปัญหาได้จริง ไม่มีของเผื่ออนาคต**

- ไม่ทำฟีเจอร์เกินที่สั่ง
- ไม่สร้าง abstraction ให้โค้ดที่ใช้ที่เดียว
- ไม่ใส่ "ความยืดหยุ่น"/config ที่ไม่มีใครขอ
- ไม่ดัก error ของเคสที่เป็นไปไม่ได้
- เขียนไป 200 บรรทัดแล้วเห็นว่าเหลือ 50 ได้ → เขียนใหม่

เกณฑ์วัด: "senior engineer เห็นแล้วจะบอกว่าซับซ้อนเกินไปไหม" ถ้าใช่ → ตัด

## 3. ผ่าตัดเฉพาะจุด (Surgical Changes)

**แตะเฉพาะที่ต้องแตะ เก็บกวาดเฉพาะสิ่งที่ตัวเองทำเลอะ**

ตอนแก้โค้ดเดิม:
- ห้าม "ปรับปรุง" โค้ด คอมเมนต์ หรือ format ข้างเคียงที่ไม่เกี่ยว
- ห้ามรีแฟกเตอร์ของที่ไม่ได้พัง
- เขียนตามสไตล์เดิมของไฟล์ แม้ตัวเองจะชอบอีกแบบ
- เจอ dead code ที่ไม่เกี่ยว → **บอก** ไม่ใช่ลบ

ตอนการแก้ของตัวเองทำให้เกิดของกำพร้า:
- ลบ import/ตัวแปร/ฟังก์ชันที่ **การแก้ของเรา** ทำให้ไม่ถูกใช้แล้ว
- ห้ามลบ dead code ที่มีอยู่ก่อน เว้นแต่ถูกสั่ง

บททดสอบ: ทุกบรรทัดที่เปลี่ยน ต้องลากกลับไปหาคำขอของผู้ใช้ได้

## 4. ทำงานโดยมีเกณฑ์ชี้ขาด (Goal-Driven Execution)

**นิยาม success criteria ก่อน แล้ววนจนกว่าจะพิสูจน์ได้**

แปลงงานให้เป็นเป้าที่ตรวจสอบได้:
- "ใส่ validation" → "เขียน test ของ input ที่ผิด แล้วทำให้ผ่าน"
- "แก้บั๊ก" → "เขียน test ที่ทำให้บั๊กโผล่ แล้วทำให้ผ่าน"
- "รีแฟกเตอร์ X" → "test ต้องผ่านทั้งก่อนและหลัง"

งานหลายขั้น ให้วางแผนสั้นๆ ก่อน:
```
1. [ขั้นตอน] → ตรวจด้วย: [วิธีตรวจ]
2. [ขั้นตอน] → ตรวจด้วย: [วิธีตรวจ]
3. [ขั้นตอน] → ตรวจด้วย: [วิธีตรวจ]
```

เกณฑ์ที่แข็งแรงทำให้วนงานเองได้จนจบ · เกณฑ์อ่อน ("ทำให้มันใช้ได้") = ต้องกลับมาถามผู้ใช้ตลอด

## จุดต่างจาก Ponytail

Ponytail คุม **ปริมาณ** ที่เขียน (ขี้เกียจให้ถูกวิธี) · วิถีคาร์พาธีคุม **วินัย** ตอนลงมือ (ไม่เดา ไม่เลย ไม่ลอย)
ใช้คู่กันได้ ไม่ขัดกัน — ถ้าขัดกันเมื่อไหร่ ให้ยึด "ตรวจสอบได้" มาก่อน "สั้น"
